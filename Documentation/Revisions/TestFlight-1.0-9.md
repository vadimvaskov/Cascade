# Cascade — TestFlight 1.0 (9)

Сборка **1.0 (9)** исправляет карту **Dark Bass Drop**: `pulse-2` использует непрерывный пульс 176 BPM вместо переключений фазы прежней `onsets-1`. На тех же записанных касаниях с прежней поправкой **+142 мс** пересчёт даёт **53 попадания / 3 промаха** вместо **39 попаданий / 12 промахов / 5 исключённых ходов**. Это повтор через модель, а не новая попытка на телефоне.

Статус на **7 ноября 2026**: **1.0 (9) доступна в TestFlight группе Internal из 9 тестировщиков**. Загрузка завершилась 6 ноября в **20:46:37 UTC** (`EXPORT SUCCEEDED`); обработка Apple завершена, группа подтверждена на карточке этой сборки. Новый прогон Dark на физическом iPhone ещё ожидается. История предыдущей версии — [1.0 (8)](TestFlight-1.0-8.md).

## Изменение Dark и результаты проверки

В реальном журнале прежней карты после 46 с ровные касания получали ошибки примерно +170–257 мс. Независимый анализ аудио обнаружил переключение фазы карты примерно на 170 мс при смене басового рисунка. Новый пульс рассчитан по аудио, без подгонки под журнал или пользовательскую поправку. Карта содержит **683 метки**, исключённых интервалов нет; `verified=false`, слуховая приёмка остаётся открытой. Подробности — в [анализе музыки](../AudioAnalysis.md).

Строгий повтор исходного журнала восстановил оценки ритма, серии, множители, каскады, занятость поля и **13 420 очков** без расхождений. С новой картой те же ходы дают **14 650 очков**, максимальную серию 26 и ×7; все десять прежних промахов после 46 с становятся попаданиями. Три промаха остаются: окно не расширялось ради результата. Источники в `Builds/iOS`: `device-dark-recovery-confirmed-pull.json`, `dark-device-replay-baseline.json`, `dark-device-replay-pulse-2.json`.

Через Unity MCP прошли **девять наборов проверок**:

| Проверка | Результат |
|---|---|
| `CascadeChecks.Run` | PASS: правила поля и каскадов |
| `CascadeRhythmChecks.Run` | PASS: окна, поправки, серия и ×1–×10 |
| `CascadeCalibrationChecks.Run` | PASS: оценка поправки |
| `CascadeBuildValidation.Run` | PASS: ресурсы, аудио и карты |
| `CascadeRecoveryChecks.Run` | PASS: 682 / 681 / 682 восстановления при 0 / +142 / −80 мс |
| `CascadeRecoveryChecks.RunAudioCadence` | PASS: обе группы независимых аудиоимпульсов; старая карта не проходит эту проверку |
| `CascadeRuntimeChecks.Run` | PASS: игровая интеграция и ввод |
| `CascadeRuntimeChecks.RunCalibrationIntegration` | PASS: применение/отмена настройки и прерывания |
| `CascadeRecoveryChecks.RunRuntimeCadence` | PASS: native36-касания, промах, восстановление серии и ×2 |

Сводка: `Builds/iOS/rhythm-validation-1.0-9.json`. Эти проверки не измеряют акустическую задержку телефона. Новая карта ещё требует реального прогона; статус трёх карт остаётся `analysisPassed=true`, `verified=false`, `reviewStatus=automated-review-pending-listen`.

## Архив, предварительная проверка и загрузка

Команды выполняются из корня проекта. Используется установленный Xcode **26.6** и существующая учётная запись разработчика в Xcode; секреты в командах не нужны.

```sh
export DEVELOPER_DIR="/Users/anastasiavaskova/Downloads/Xcode.app/Contents/Developer"
xcrun xcodebuild -version
```

Архивирование экспортированного Unity-проекта:

```sh
xcrun xcodebuild \
  -project Builds/iOS/Xcode/Unity-iPhone.xcodeproj \
  -scheme Unity-iPhone \
  -configuration Release \
  -sdk iphoneos \
  -destination 'generic/platform=iOS' \
  -archivePath Builds/iOS/Cascade-1.0-9.xcarchive \
  -derivedDataPath Builds/iOS/DerivedData \
  -jobs 4 \
  -allowProvisioningUpdates \
  DEVELOPMENT_TEAM=RUT46C38YA \
  CODE_SIGN_STYLE=Automatic \
  archive > Builds/iOS/archive-1.0-9.log 2>&1
```

После `ARCHIVE SUCCEEDED` проверить подпись, профиль, Bundle ID, версию, архитектуру, privacy manifests и UUID dSYM:

```sh
python3 Tools/verify_ios_archive.py \
  Builds/iOS/Cascade-1.0-9.xcarchive \
  --version 1.0 \
  --build 9 \
  --report Builds/iOS/preflight-1.0-9.json \
  --allow-missing-framework-dsym UnityRuntime.framework
```

Preflight **1.0 (9) пройден**: Bundle ID, версия, профиль, подпись, arm64, privacy manifests и dSYM приложения/UnityFramework проверены. Единственное предупреждение — отсутствующий dSYM пустой заглушки `UnityRuntime`: журнал этого архива подтверждает `Injecting stub binary into codeless framework`. UUID настоящего UnityFramework — `067756B6-ECF9-3516-AAC8-763CEED28FD7`, совпадение с его dSYM проверено. Искусственные символы не создавались. Архивный `resources.assets` полностью совпадает с проверенным Unity export; новая карта и обе прежние карты находятся внутри приложения.

После успешной проверки следующая команда **загружает сборку** согласно `destination=upload` в plist:

```sh
xcrun xcodebuild -exportArchive \
  -archivePath Builds/iOS/Cascade-1.0-9.xcarchive \
  -exportPath Builds/iOS/export-1.0-9 \
  -exportOptionsPlist Tools/ExportOptions-TestFlight.plist \
  -allowProvisioningUpdates > Builds/iOS/upload-1.0-9.log 2>&1
```

**Публикация 1.0 (9) подтверждена:** [карточка сборки в App Store Connect](https://appstoreconnect.apple.com/teams/2a2b9828-a50d-4a91-8201-d046537c8f16/apps/6827096867/testflight/ios/68d5e674-c25e-4069-b78f-54855d786a86), отчёт `Builds/iOS/published-1.0-9.json`. ## Проверка на телефоне после установки 1.0 (9)

1. Проверить номер **1.0 (9)** в TestFlight. Использовать тот же динамик или наушники. На уже проверенном iPhone сохранённая поправка **+142 мс** остаётся действующей; это индивидуальное значение, не обязательная настройка для остальных устройств.
2. Запустить **Dark Bass Drop** и проверить ровные постановки на участке **40–60 с**, особенно после **46 с**, продолжая привычный темп. Проверить, что смена басового рисунка не превращает следующие ровные касания в постоянные промахи.
3. Сделать один намеренный промах, затем вернуться к ритму после окончания реакции. Новое попадание должно начать серию заново; четыре последовательных попадания дают ×2. Повторить восстановление в другой части трека.
4. По возможности пройти Dark полностью, отдельно обратить внимание на вступление и затухание. Проверить паузу/возобновление, мерцание, каскады, Safe Area, плавность и звук.
5. При повторении проблемы нажать паузу и сохранить время участка, поправку и счётчики попытки до запуска следующего уровня: приложение хранит один последний журнал.

Полный Midnight Floor уже подтверждён пользователем **в сборке 8**: 181 принятый ход, 179 попаданий, 1 промах и 1 ход в свободном ритме, **178 510 очков**, ×10, +142 мс. Это один полный трек на физическом устройстве; прохождение новой Dark и полная проверка Drop Bass Princess остаются открытыми. Подробнее — в [Validation.md](../Validation.md).

## Настройка ритма

Функция доступна с версии 1.0 (8). Откройте **Настройка ритма** из меню или паузы → **Начать проверку**. Первые два щелчка — разминка, затем нужно десять ровных касаний по кнопке в такт звуку. Настройка сохраняется только через **Применить**; выход и прерывание оставляют прежнее значение. При смене наушников/динамика измерение следует повторить. Допускается ручная поправка ±400 мс с шагом 10 мс.

Проверяйте подтверждение попадания, прогресс до следующего множителя, сообщения рано/поздно и мерцание с поправкой. До четвёртого попадания множитель остаётся ×1. Общая ненулевая поправка всем устройствам не назначалась.

Исправление нативного ввода из сборки 7 сохранено: phase, touchId и position читаются из короткого события отдельно, исходный timestamp сохраняется. Проверки native36 входят в текущий набор; история исправления — [TestFlight 1.0 (7)](TestFlight-1.0-7.md).
