# Cascade — Unity prototype 02

> **Актуальная рабочая версия:** [Updates/V3](Updates/V3/README.md), TestFlight **1.0 (14)**. Открывать в Unity 6000.6.8f1 папку `Updates/V3`. Корень сохраняет предыдущую базовую версию проекта. Статус выпуска: [TestFlight](Updates/V3/Documentation/TestFlight.md).


Игровой прототип с полем 6×6, музыкальными сферами, синхронизацией с треками и множителем ×1–×10. Текущий игровой экран перенесён из пакета `Cascade_Raster_Assets` по макету 941×1672. Текущий этап предназначен для проверки оформления и ритмической механики; карты долей пока имеют статус предварительных.

## Запуск и управление

Открыть проект в **Unity 6000.6.8f1**, выбрать **Cascade → Open prototype**, затем **Play**. Сцена: `Assets/Scenes/CascadePrototype.unity`. Для сверки макета предусмотрена Game View `Cascade reference` 941×1672; для вытянутого экрана — `Cascade tall phone` 1170×2532.

- Выбрать один из трёх треков и дождаться отсчёта 3–2–1.
- Коротко коснуться свободной клетки или кликнуть мышью: появится следующая сфера. Постановка выполняется сразу; близость к музыкальной доле определяет ритмическую награду.
- Кнопка **II** открывает паузу. Доступны продолжение, повтор, меню, громкость, уменьшенные эффекты и настройка ритма. Повтор и выход из паузы требуют подтверждения.
- **F1** в редакторе открывает панель разработчика: seed, поправка −400…+400 мс с шагом 10 мс и экспорт текущей попытки на паузе.

В **1.0 (8)** добавлена необязательная калибровка; сборка доступна в TestFlight. Для проверки после обновления:

1. В меню или на паузе открыть **«НАСТРОЙКА РИТМА» → «НАЧАТЬ ПРОВЕРКУ»**.
2. Прослушать первые **2 щелчка для разминки**, затем сделать **10 ровных касаний** кнопки в такт звуку, используя тот же динамик, с которым будете играть.
3. Нажать **«ПРИМЕНИТЬ»** и проверить **Midnight Floor**. Неровное измерение предложит повтор; выход без применения сохраняет прежнюю настройку.

Поправка подбирается для конкретного игрока и устройства; предусмотрена ручная настройка ±400 мс. Общая ненулевая поправка для всех игроков не задана. Сообщения показывают попадание, прогресс до следующего множителя либо «рано/поздно» в миллисекундах.

Прототип открывается аддитивно; Play запускает `CascadePrototype` через `playModeStartScene`. Исходные `SampleScene` и `ConnectionTest` сохранены. Снимок первого этапа — сцена, прежний скрипт и превью — находится в `Documentation/Revisions/Prototype01`.

## Правила и ритм

Правила размещения и каскадов сохранены: поле 6×6, начальные 6 сфер, заряды появления 1/2/3 с весами 60/30/10. Постановка даёт +1 занятым соседям по стороне. При заряде ≥5 сферы взрываются одновременными волнами. После всех волн появляется одна пассивная автосфера. Поле проверяется на заполнение после расчёта полного хода; ввод во время реакции закрыт.

Очки хода: **(10 + 50 × уничтоженные сферы) × множитель хода**. Множитель фиксируется один раз для всех волн:

| Серия успешных постановок | Множитель |
|---|---:|
| 0–3 | ×1 |
| 4–7 | ×2 |
| 8–11 | ×3 |
| Далее каждые 4 попадания | +1 ступень |
| 36 и больше | ×10 |

Принятый промах сбрасывает серию и множитель до ×1. Повторная постановка в уже использованную долю получает ×1 и сохраняет серию, не продлевая её таймер. Ходы в исключённых интервалах также получают ×1 и не добавляют ритмических наград. Занятые клетки, второй палец и закрытый ввод не расходуют следующую сферу и не меняют серию. Тайм-аут — 10 секунд активного ритмического времени; паузы и исключённые интервалы не учитываются.

Окно попадания — ±120 мс, ограниченное 45% расстояния до соседней доли. Оценивается исходное время Input System, переведённое в шкалу DSP. Положительный offset компенсирует позднее время касания относительно доли. Свет пульсирует по той же карте долей с учётом применённой поправки; серия усиливает свечение, не повышая частоту. На паузе останавливаются музыкальная и визуальная шкалы.

## Графика и ресурсы

Текущий игровой экран использует оригинальные PNG из переданного пакета: один фон, одно пустое поле, логотип, паузу и четыре состояния сфер. Координаты, пропорции и прозрачные поля сохранены по `Assets/Cascade/Art/Raster/Layout_941x1672.json`. Все 36 сфер — отдельные подвижные слои Canvas, связанные с существующей моделью и 3D-коллайдерами клеток. Проект продолжает использовать URP; прежние процедурные оболочки и фон в игровом экране скрыты.

Счёт, ×1–×10, трек, время, прогресс и следующая сфера обновляются из игры. `hud-overlay.png` хранится только как образец и не входит в зависимости сцены. Свечение клеток/рамки, появление сфер и импульс каскада реализованы отдельно. Все декоративные слои пропускают касания. Композиция равномерно вписывается в Safe Area, фон заполняет экран без растяжения пропорций.

[Превью Unity по контрольной раскладке](Documentation/Preview-Raster.png) · [Перенос и ограничения сверки](Documentation/RasterDesign.md). Расстановка из JSON включается только командой **Cascade → Show supplied layout fixture (Play Mode only)** и не меняет стартовую раскладку игры. Шрифт для живых надписей в пакете отсутствует; используется существующий LegacyRuntime с настроенными размером, интервалами и мягким свечением. Попиксельное совпадение с нарисованным текстом не заявлено. Новое оформление доступно в TestFlight **1.0 (10)** группе Internal (9 тестировщиков). Проверки Editor пройдены; проверка оформления на физическом телефоне ещё нужна.

Сборка оформления — `CascadeGame.Raster.cs`; `CascadeGame.Visuals.cs` сохраняет прежние меню и диалоги. Исходники до переноса находятся в `Documentation/Revisions/BeforeRaster`. Cormorant Garamond Italic остаётся для прежних экранов и отсчёта, лицензия SIL OFL 1.1 находится в `Art/Fonts/OFL-Cormorant.txt`.

Персонажи, погоня, порталы и боссы не входят в этот этап. Новые Unity-пакеты не устанавливались; версии редактора и существующих пакетов сохранены. ТЗ первоначально указывает Unity 6.3 LTS, тогда как этот проект уже использовал 6000.6.8f1.

## Музыка и статус карт

Все три полных трека импортированы как streaming/Vorbis, quality 0.8. Производные PCM WAV 48 kHz stereo подготовлены из предоставленных Opus `.m4a`; исходники не изменены. Длительности AudioClip: **187.2135 / 181.1335 / 232.7735 с**.

Карты работают в игре: `analysisPassed: true`, `verified: false`, `reviewStatus: "automated-review-pending-listen"`. Первые две карты `onsets-1` следуют атакам по всей записи. Для Dark Bass Drop подготовлена **`pulse-2`**: непрерывный пульс **176 BPM**, 683 метки, обе чередующиеся доли допустимы. Его фаза проверена отдельным PCM-детектором по всей песне; максимальное расхождение по 16-секундным окнам — 19,482 мс. Прежняя карта Dark смещала фазу примерно на 170 мс и исключала короткие участки с продолжающейся музыкой.

Исправление Dark опубликовано в TestFlight **1.0 (9)** для группы Internal. Повтор реального журнала в Unity при прежних +142 мс даёт **53 попадания / 3 промаха** вместо **39 / 12 / 5 ходов без оценки**. Это пересчёт прежних касаний, не результат новой игры на телефоне. Музыка, остальные карты, правила поля, блокировка 350 мс и окно ±120 мс сохранены. Более плотная музыкальная карта увеличивает число допустимых долей; рекорд Dark отделён новой версией. Слуховая проверка вступления/конца и испытание новой сборки на телефоне ещё ожидаются.

Перед сборкой `CascadeBuildValidation` проверяет SHA-256 реальных WAV, импортированную длительность и структуру карты. При запуске уровня карта сверяется с манифестом аудио и длительностью AudioClip; несовпадение блокирует подготовку. Рекорды разделены по версии баланса и карты. Журнал содержит статус карты, поэтому предварительные результаты можно отличить от будущей проверенной версии.

Метод, метрики и команды воспроизведения анализа: [Documentation/AudioAnalysis.md](Documentation/AudioAnalysis.md). **Автоматические проверки не заменяют прослушивание и калибровку на физическом iPhone.**

## Настройки и проверки

Баланс хранится в `Assets/Cascade/Resources/Data/balance.json` (`prototype-2`), карты и манифест — рядом. Модель правил и ритма — `CascadeModel.cs`, управление попыткой — `CascadeGame.cs`. Локальный журнал: `Application.persistentDataPath/cascade-last-attempt.json`.

| Команда меню Cascade | Назначение |
|---|---|
| Run model checks | Исходные правила G01–G08/R01–R07 и 100 симуляций |
| Run rhythm x10 checks | Ступени ×1–×10, границы окна, тайм-ауты, порядок событий и карты |
| Run rhythm calibration checks | Оценка поправки, разминка, устойчивость к выбросам и отклонение неровных касаний |
| Verify audio and maps | Контрольные суммы, длительности и данные трёх треков |
| Run runtime integration checks (Play Mode) | Проверка связки ввода, модели, очков, паузы и результата |
| Run calibration integration checks (Play Mode) | Экран калибровки, исходные timestamps, применение/отмена и прерывания |
| Run Dark rhythm recovery checks | Восстановление серии после промаха, тайм-аута и исключений |
| Run independent Dark audio cadence regression | Обе чётности измеренного PCM-пульса и восстановление после промаха |
| Run Dark native cadence recovery (Play Mode) | Те же сценарии через нативные 36-байтовые касания и реальное поле |
| Verify raster layout and input (Play Mode) | Касания по JSON, живой HUD, сферы и эффекты; затем прежние интеграционные проверки |
| Rebuild prototype visuals | Пересоздание сцены с текущим растровым оформлением |

Runtime-проверки заменяют текущую попытку контрольными раскладками и возвращают игру в меню. Пересборка визуальной сцены заменяет её ручные правки. Результаты проверок и их границы: [Documentation/Validation.md](Documentation/Validation.md).

Полное естественное прохождение всех трёх треков, слуховая приёмка карт и профилирование физического iPhone 17 Pro ещё не выполнены. Текущая опубликованная сборка — iOS Release **1.0 (10)** для группы Internal; подробности — в [отчёте TestFlight](Documentation/TestFlight.md). В предыдущей 1.0 (7) пользователь подтвердил постановку сфер на физическом iPhone, затем сообщил о проблеме зачёта слышимого ритма через встроенный динамик.

В реальном журнале Midnight Floor записаны 51 попадание и 78 промахов, медиана ошибки +122,914 мс. Программный повтор тех же ходов с поправкой +100 мс даёт **113 попаданий вместо 51**; это модель возможной компенсации, а не новый результат на телефоне и не основание назначать +100 мс всем. Измерение включает восприятие, ввод, вывод и привязку часов; чистая аудиозадержка отдельно не измерена.

Новые чистые и интеграционные проверки калибровки, прежние проверки runtime/правил/ритма и проверка аудио/карт прошли **PASS через Unity MCP**. **1.0 (8)** опубликована в TestFlight для группы Internal; пользователь подтвердил нормальный зачёт и завершил Midnight Floor на iPhone: **181 ход = 179 попаданий + 1 промах + 1 ход в свободном ритме**, 178 510 очков, серия 179, ×10, поправка +142 мс. Повтор журнала через Unity MCP совпал без расхождений. Карты и игровые правила сохранены. Также остаются проверка Safe Area на устройстве и дальнейшая художественная доводка.
