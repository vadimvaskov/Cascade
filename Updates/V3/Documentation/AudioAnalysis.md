Карты относятся к WAV, импортированным в Unity. У всех сохранены `analysisPassed: true`, `verified: false`, `reviewStatus: "automated-review-pending-listen"`: автоматические проверки пройдены, полная слуховая приёмка ещё требуется. Новая карта Dark Bass Drop `pulse-2` требует отдельного игрового прогона на телефоне; результаты моделирования ниже не заменяют его.

| Трек | Версия | Длительность | Темп | Меток / вне исключений | Исключено времени |

| Midnight Floor | `onsets-1` | 187.2135 с | 109.983 BPM — опора трекера | 342 / 335 | 2.48% |

| Dark Bass Drop | `pulse-2` | 232.7735 с | **176 BPM**, непрерывная фаза | **683 / 683** | **0%** |

Исходная музыка и WAV не изменены. SHA-256, длительности, порядок и диапазон меток проверяются отдельно от музыкальной оценки. Калибровка устройства не записывается в карту.

## Midnight Floor и Drop Bass Princess

Метод `spectral-flux-dp-v1` сохранён. `onsets.cpp` анализирует моносумму PCM при 12 kHz: Hann 1024 отсчёта, шаг 10 мс, положительный спектральный поток в диапазонах до 180 Hz, 180–1400 Hz и выше 1400 Hz. Их веса — 0.65 / 0.25 / 0.10. Динамическое программирование выбирает атаки с ограничением изменения периода; недостаточно подтверждённые участки исключаются.

Метки этих двух карт следуют атакам. Midnight практически равномерен: аппроксимация даёт 110.004 BPM, P95 отклонения меток от постоянной сетки 12.8 мс. В Princess сам сигнал ускоряется примерно с 128 до 131.5 BPM; заменять его одной сеткой среднего темпа нельзя. Квантованный `medianBpm` в JSON не равен опорному темпу трекера.

Независимый контроль использует FFmpeg low-pass 180 Hz, mono 6 kHz, RMS 10 мс и положительные скачки энергии:

| Трек | Совпавшие / оцениваемые метки | Доля совпадений | Медиана signed error | P95 абсолютной ошибки |
|---|---:|---:|---:|---:|
| Midnight Floor | 331 / 335 | 98.81% | +2.33 мс | 22.3 мс |
| Drop Bass Princess | 355 / 358 | 99.16% | +2.00 мс | 22.3 мс |

Положительный знак означает, что RMS-атака позже метки. Эти показатели подтверждают согласованность с атаками сигнала; они не измеряют задержку динамика, ОС и сенсора.

## Dark Bass Drop: исправление фазовых скачков

Прежний `onsets-1` следовал преимущественно басовым атакам около 88 BPM. При смене рисунка он переходил на соседние акценты: после 44–45 с фаза сдвигалась примерно на 170 мс, позже происходили другие переходы. Это превышало игровое окно **±120 мс**. Дополнительно карта содержала 51 исключение; 45 были короче секунды и преимущественно отражали слабую отдельную атаку, а не тишину. Поэтому ровные касания могли перестать оцениваться после смены рисунка.

Новый `dark_pulse_map.py` строит сетку **176 BPM с первой меткой 0.255 с** (`continuous-highband-pulse-v2`, версия `pulse-2`). Время каждой следующей метки увеличивается на 60/176 с. Фаза больше не переключается вслед за басовыми акцентами; обе чередующиеся группы ударов доступны для ритмической оценки.

Параметры выбраны только по аудио:

- Высокочастотный спектральный поток в 16–224 с даёт оценку **175.992 BPM**. Отличие фиксированных 176 BPM соответствует лишь 10.581 мс за всю запись.
- Максимум спектральных атак по фазе — **254.428 мс**; он округлён до **255 мс**. Фаза не получена из касаний или настройки задержки.
- Фазовая когерентность высокочастотного сигнала: 176 BPM — **0.142109**, 88 BPM — 0.006242, 117.333 BPM — 0.006015. Прежний сильный басовый пик около 117 BPM не задавал устойчивую общую фазу перкуссии.
- 88 BPM остаётся возможным восприятием ритма вдвое медленнее. Для игры выбран слышимый пульс 176 BPM, чтобы не отвергать каждую вторую группу подтверждённых атак.

Исключения теперь требуют непрерывного участка broadband RMS ниже 0.006 длительностью не менее секунды. В этой записи таких участков не найдено; одиночные слабые басовые атаки больше не отключают награду. Правила размещения, реакция 350 мс, окно ±120 мс и пользовательский offset не изменены картой.

## Независимая проверка Dark

Проверяющий алгоритм повторно декодирует **сам WAV**, не используя FFT-признаки генератора: high-pass 1500 Hz → mono 12 kHz → RMS 10 мс → положительные атаки. В каждом 16-секундном окне определяется максимум фазового распределения при 176 BPM по всей фазовой окружности.

| Измерение | Результат |
|---|---:|
| Фаза независимых атак в 16–224 с | 259.442–264.455 мс |
| Максимальная ошибка фазы окна по всей записи | **19.482 мс** |
| Метки с независимой атакой в пределах ±40 мс | **99.56%** |
| Медиана расстояния до ближайшей атаки | 6.364 мс |
| P95 расстояния | **22.636 мс** |

±40 мс здесь — критерий аудиоанализа; игровое окно остаётся ±120 мс. Основной критерий приёмки — стабильная фаза независимого измерителя по всей записи. Контрольная сетка, намеренно сдвинутая на половину периода, не проходит этот тест.

Вступление и затухание требуют особого внимания: фаза широкополосного PCM-контроля составляет 271.975 мс в 0–16 с и 274.482 мс в последнем окне. Дополнительная узкополосная проверка 3.2–5.5 kHz обнаруживает во вступлении также сильную другую поддолю, примерно на 158 мс раньше сетки. Это ограничивает уверенность в воспринимаемом метре начала трека; автоматическая проверка не заменяет прослушивание. Последняя метка 232.755 с расположена близко к концу файла: фактическое окно ввода дополнительно ограничено окончанием песни.

Карта построена **только по аудио**. Отдельный пересчёт одной реальной попытки с неизменным offset +142 мс дал:

| Карта | Попадания / промахи / исключения |
|---|---:|
| Прежняя `onsets-1` | 39 / 12 / 5 |
| Непрерывный вариант 88 BPM | 52 / 4 / 0 |
| Новая `pulse-2`, 176 BPM | **53 / 3 / 0** |

Все десять повторявшихся промахов после 46 с стали попаданиями. Это модельный пересчёт тех же касаний, а не повторно сыгранная попытка. Оставшиеся промахи не маскируются расширением окна или подгонкой карты.

## Воспроизведение

Нужны C++ compiler, стандартный Python и FFmpeg. Дополнительные Unity-пакеты не требуются. Для свежих FFT-признаков:

```sh
clang++ -O2 -std=c++17 Tools/Audio/onsets.cpp -o /tmp/cascade-onsets
mkdir -p /tmp/cascade-audio-analysis
/tmp/cascade-onsets 'Assets/Cascade/Resources/Audio/Midnight Floor.wav' '/tmp/cascade-audio-analysis/Midnight Floor.csv'
/tmp/cascade-onsets 'Assets/Cascade/Resources/Audio/Drop Bass Princess.wav' '/tmp/cascade-audio-analysis/Drop Bass Princess.csv'
/tmp/cascade-onsets 'Assets/Cascade/Resources/Audio/Dark Bass Drop.wav' '/tmp/cascade-audio-analysis/Dark Bass Drop.csv'
```

Проверка без публикации карт; `validate_maps.py` проверяет текущие Resources, `dark_pulse_map.py --check` заново строит и проверяет Dark в памяти:

```sh
python3 -B Tools/Audio/dark_pulse_map.py --check --ffmpeg /tmp/cascade-ffmpeg
python3 -B Tools/Audio/validate_maps.py --ffmpeg /tmp/cascade-ffmpeg
```

Явная перезапись **только карты Dark**:

```sh
python3 -B Tools/Audio/dark_pulse_map.py --write --ffmpeg /tmp/cascade-ffmpeg
```

Общая пересборка карт, манифеста и отчётов:

```sh
python3 -B Tools/Audio/build_maps.py --write --ffmpeg /tmp/cascade-ffmpeg
python3 -B Tools/Audio/validate_maps.py --write --ffmpeg /tmp/cascade-ffmpeg
```

Общий генератор направляет Dark в новый модуль и не возвращает басовый DP-трекер. Общий валидатор требует для Dark `pulse-2` и проверяет независимую фазу перкуссии; для двух других треков сохранён контроль низкочастотных атак. Детали находятся в `AudioAnalysis.json`/`.csv`: `independentPulseCheck.phaseWindows` для Dark и `independentEnvelopeCheck` для остальных. `--candidate-dir` нового модуля позволяет отдельно сохранить сравнение 176/88 BPM без публикации в Resources.
